# UI-источники ДокМаркета

Этот файл — карта внешних источников для дизайна. Они не заменяют дизайн-систему ДокМаркета. Любой взятый паттерн сначала адаптируется к нашим цветам, типографике, радиусам, плотности и mobile-first логике.

## 1. tweakcn.com

Назначение: настройка темы shadcn/ui и быстрый поиск удачных сочетаний цветов, типографики, радиусов, теней и плотности.

Использовать для:
- проверки палитры;
- настройки контраста;
- поиска значений radius/spacing/shadow;
- сравнения нескольких вариантов одной темы;
- экспорта токенов как отправной точки.

Не использовать для:
- полного визуального переезда ДокМаркета на чужой preset;
- копирования темы без адаптации;
- смешивания нескольких preset-стилей на разных страницах.

Правило для ДокМаркета: сначала сохраняем существующую тёмно-синюю/золотую основу, затем используем tweakcn только для выравнивания токенов и контраста.

Источник: https://tweakcn.com/

## 2. icon-sets.iconify.design

Назначение: единый поиск по большому количеству открытых наборов иконок.

Использовать для:
- понятных UI-иконок навигации;
- статусов заказа;
- категорий документов;
- корзины, избранного, профиля, поиска;
- продавца, проверки, оплаты, файла, загрузки.

Базовое правило:
- на одном экране использовать один основной стиль иконок;
- для обычного UI предпочтительны Tabler, Phosphor, Material Symbols или другой единый набор;
- перед включением конкретной иконки в production проверить лицензию набора;
- не использовать эмодзи вместо системной иконки там, где это элемент интерфейса.

Источник: https://icon-sets.iconify.design/

## 3. 3dicons.co

Назначение: 3D-иллюстрации для маркетинговых и пустых состояний.

Использовать точечно:
- пустая корзина;
- успешная покупка;
- проверенный продавец;
- безопасный заказ;
- загрузка документа;
- onboarding продавца;
- крупные hero/feature-секции, где 3D действительно помогает понять действие.

Не использовать:
- как иконки кнопок;
- в каждой карточке каталога;
- в таблицах и плотных рабочих интерфейсах;
- если 3D-объект ухудшает скорость загрузки или визуально спорит с контентом.

Для production оптимизировать формат и размер ассета. Не тянуть исходники тяжелее, чем нужно для фактического размера отображения.

Источник: https://3dicons.co/

## 4. 21st.dev

Назначение: библиотека готовых React/shadcn паттернов и компонентов.

Использовать как референс или основу для:
- hero;
- карточек каталога;
- поиска;
- AI-чата;
- навигации;
- authentication UI;
- pricing / checkout блоков;
- empty states;
- mobile drawers;
- seller dashboard;
- анимаций и микровзаимодействий.

Правила интеграции:
1. Не копировать компонент вслепую.
2. Сначала понять его UX-задачу.
3. Оставить только нужную механику.
4. Перевести цвета, размеры, radius, typography и hover/focus states на токены ДокМаркета.
5. Удалить лишнюю зависимость, если компонент можно реализовать уже установленным стеком.
6. Проверить keyboard/focus и мобильную версию.

Источник: https://21st.dev/

## 5. bloub.vercel.app

Назначение: визуальный референс, если конкретный экран или эффект оттуда полезен для ДокМаркета.

Правило: не подключать как зависимость и не копировать код, пока не проверены фактический компонент, лицензия и техническая необходимость. Если используется только внешний вид — воспроизвести идею средствами текущего проекта.

Источник: https://bloub.vercel.app/

## Приоритет использования

Для обычной продуктовой задачи порядок такой:

1. Сначала существующие компоненты и токены ДокМаркета.
2. Затем 21st.dev — если нужен новый UX-паттерн.
3. Iconify — подобрать согласованную иконку.
4. tweakcn — выровнять тему/контраст/радиусы/тени.
5. 3dicons — только если нужен иллюстративный акцент.
6. bloub — только как дополнительный визуальный референс после проверки.

## Что особенно нужно ДокМаркету

При следующих UI-задачах искать референсы именно под сценарий, а не просто «красивый блок»:

- Главная: marketplace search + категории + популярные документы + проверенные продавцы.
- Карточка документа: preview + цена + продавец + состав покупки + основное CTA.
- Карточка услуги: цена «от» + срок + что входит + кто выполняет + заказать.
- Корзина: компактный список + итог + объяснение безопасной сделки.
- Заказ услуги: timeline статусов + файлы + сообщения + подтверждение результата.
- Кабинет покупателя: покупки, услуги, документы, статусы.
- Кабинет продавца: товары, услуги, модерация, заказы, рейтинг.
- AI-помощник: компактная плавающая кнопка, затем нормальный диалог, а не окно поверх половины мобильного экрана.

## Антипаттерны

Не делать:
- несколько разных стилей кнопок на одной странице;
- случайные 3D-иконки рядом с line-icons;
- декоративные CTA без работающего действия;
- слишком крупные карточки на телефоне;
- горизонтальное меню, которое обрезается без очевидного скролла;
- слабый контраст текста;
- новый компонент только потому, что он эффектный в библиотеке;
- внешнюю анимацию, которая мешает покупке документа или оформлению заказа.
